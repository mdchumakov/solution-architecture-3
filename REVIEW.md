Проверено 16 октября 2026 года. Документы описывают проектное решение; пилот в магазинах не проводился.

| --- | --- | --- |
| Карта L1/L2, красные проблемные зоны, зелёное преимущество | [Task1](Task1/README.md), [карта](Task1/capabilities.svg) | Уровни, владельцы и легенда показаны |
| Buy / Build / Migrate / on-premises | [Матрица решений](Task1/README.md#матрица-buy-vs-build) | Стандартные функции отделены от собственной логистики |
| BPMN 2.0, пулы людей и систем, данные SKU | [Процесс](Task2/onboarding.bpmn) | Проверен по официальным XSD OMG; импорт в bpmn-js 18.6.2 без предупреждений |
| Проверка человеком и исправление ошибок | [Task2](Task2/README.md#как-проверяем-соответствия) | Есть исключения, выборка, блокировка и повторная проверка |

| Простые формулировки | README каждого задания | Редактура по humanizer: убраны общие обещания, названы исполнители, допущения отделены от результатов |

У BPMN проверены уникальность идентификаторов, существование концов стрелок, отсутствие sequence flow между пулами, достижимость действий от начала и путь к завершению. Это проверка структуры описательной модели, а не доказательство работы производственного процесса.

Четыре SVG просмотрены в браузере. В [просмотрщике](diagrams.html) проверены переключение схем, масштаб 100%, увеличение и подгонка по ширине. Ошибок JavaScript нет. Ссылки на локальные файлы разрешаются.

Повторяемая проверка TCO: `python3 Task4/calculate.py --check`. Денежные предположения требуют подтверждения. В частности, план на 3 FTE и отсутствие массовой замены терминалов влияют на достижение 40% экономии.

Исходные файлы в `docs/` и `AGENTS.md` не редактировались. Пробелы в конце некоторых строк исходных заданий сохранены; в новых Markdown-файлах таких ошибок нет.

Правила нотаций проверены по [OMG BPMN 2.0.2](https://www.omg.org/spec/BPMN/2.0.2/) и [C4 Container diagram](https://c4model.com/diagrams/container). Эти источники определяют нотации; бизнес-факты взяты из материалов кейса.
