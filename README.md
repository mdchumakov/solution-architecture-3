# VitaStore: снижение затрат на магазины

Решение проектной работы № 3. Переносим стандартные функции в Cloud POS, сохраняем собственную омниканальную логистику и убираем серверы из магазинов. Наличные продажи продолжаются при обрыве связи.

| Задание | Что подготовлено |
| --- | --- |
| [Task1](Task1/README.md) | Карта возможностей L1/L2, проблемные зоны, матрица Buy vs Build |
| [Task2](Task2/README.md) | BPMN 2.0 подключения магазина, проверка SKU, план на пять рабочих дней |
| [Task3](Task3/README.md) | Исправленная AS-IS C4 Container, целевая архитектура, HAL и офлайн-режим |
| [Task4](Task4/README.md) | TCO на три года для 100 магазинов, ROI, окупаемость и чувствительность |

## Как читать решение

Исходные задания сохранены в [docs](docs/context.md). Факты из кейса, проектные решения и расчётные допущения разделены в пояснениях. Стоимости в Task4 учебные: коммерческих предложений и фактического бюджета в исходных данных нет.

В базовой модели TCO снижается с 146,4 до 83,6 млн ₽ за три года. Это результат выбранных допущений, а не подтверждённая экономия компании. Для запуска нужны пилот и проверка тарифов.

Схемы доступны как SVG; исходник процесса сохранён в формате `.bpmn`. Для просмотра с масштабированием откройте [diagrams.html](diagrams.html) локально в браузере. Файлы открываются без сборки проекта. Проверка расчёта: `python3 Task4/calculate.py --check`. Обновление таблиц после изменения допущений: `python3 Task4/calculate.py`.

## Границы решения

Пять рабочих дней отсчитываем после передачи доступа, выгрузки товаров и получения совместимого оборудования. Закупка устройств и разработка нового драйвера могут увеличить срок. SAP остаётся в центральном офисе. В магазине нет отдельного сервера БД, но планшет хранит справочники и журнал непринятых облаком продаж.

Весь кейс относится к сети из 500+ магазинов. Финансовая модель охватывает только 100 магазинов, как требует задание 4. Выводы нельзя механически умножать на пять: доля общих расходов изменится.
